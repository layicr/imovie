## 三、本轮 SEO 改造与回归结论

为满足「只读展示站应被搜索引擎收录」的目标，本次对应用做了 SSR / 元数据 / 结构化数据改造，测试套件全程用于回归验证。

### 3.1 改动清单（仅新增/调整展示层，未改数据源逻辑）

| 文件 | 类型 | 内容 |
|------|------|------|
| `app/sitemap.ts` | 新增 | 首页 + /search + /report + 全部影片详情页（`item_id` + `updated_at`） |
| `app/robots.ts` | 新增 | 允许全站、禁止 `/api/`、指向 `sitemap.xml` |
| `app/layout.tsx` | 调整 | 补全 `metadataBase`/`title.template`/`keywords`/`robots`/`canonical`/`OG`/`Twitter`，改用 `getSiteUrl()` |
| `app/detail/[id]/page.tsx` | 改为 Server Component | `generateMetadata` + Movie JSON-LD + `force-dynamic` |
| `app/detail/[id]/DetailContent.tsx` | 新增 | 客户端交互子组件（保留状态/评分交互） |
| `app/page.tsx` + `app/HomeContent.tsx` | 改为 Server Component | 首页 SSR，首屏含完整 HTML |
| `app/search/page.tsx` + `SearchContent.tsx` | 调整 | 服务端 `metadata`（noindex）+ WebSite SearchAction JSON-LD + `Suspense` |
| `app/report/page.tsx` + `ReportContent.tsx` | 调整 | 服务端预取数据 SSR |
| `app/not-found.tsx` | 新增 | 自定义中文 404 页面（修复 SSR 后默认 404 文案不匹配问题） |
| `lib/seo.ts` | 新增 | `getSiteUrl()` 统一读取 `NEXT_PUBLIC_SITE_URL`，缺省回退 `http://localhost:3000` |
| `.env.example` | 新增 | 说明 `NEXT_PUBLIC_SITE_URL` 配置 |

### 3.2 回归验证

- **Vitest 141 passed**：单元/功能测试均未因 SSR 改造受影响（数据源 `lib/queries` / `lib/validate` / `lib/poster` / `lib/config` 未改动）。
- **Playwright 58 passed**：原 2 例「不存在 item_id → 404」因 SSR 后改用 `notFound()` 渲染 Next 默认 404（"could not be found" 不匹配旧断言正则）而失败；新增 `app/not-found.tsx` 渲染中文「未找到」后两例恢复通过，全量转绿。
- **`npm run build`**：✅ Compiled successfully，SSR 路由（ƒ 动态）正常编译。
- **端点实测**：`/sitemap.xml` 200（含全部 `detail/<id>`）、`/robots.txt` 200、`/detail/__not_exist_id__` 返回 404 且含「未找到」文案。

### 3.3 风险与说明

- `lib/queries.ts` 的 `listFacets` 模块级 5 分钟缓存：功能测试已在 `beforeEach` 调用 `invalidateFacets()` 重置，无跨用例污染。
- 详情页 `force-dynamic` 保证每次请求取最新数据；若未来做 ISR 可改为 `revalidate`。
- `NEXT_PUBLIC_SITE_URL` 未设置时本地回退 localhost，生产未设置仅打印警告、不阻断构建。
