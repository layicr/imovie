# iMOVIE 代码调优与清理报告

- **日期**：2026-08-31
- **范围**：性能调优（5 项）、i18n 冗余清理（1 项）、测试验证
- **结论**：全部改动已落地，单测 / 功能测 / UI e2e / 类型检查均通过

---

## 一、背景

基于此前代码审查结论，对观影记录站点做精准的局部优化（不推翻既有结构），聚焦数据库查询去重、冗余查询消除、API 错误响应增强与分隔符拆分逻辑统一，并清理 i18n 中未被引用的冗余文案。

## 二、改动清单

### 1. 详情页查库去重（项 #1）
- 文件：`app/detail/[id]/page.tsx`
- 内容：模块级用 `cache(getRecord)` 包装为 `getRecordCached`，`generateMetadata` 与 `DetailPage` 共用。同一请求内（元数据 + 正文）对同一条记录只查一次库，减少 1 次 `SELECT`。

### 2. 首页省去 COUNT（项 #2）
- 文件：`lib/queries.ts`、`app/page.tsx`
- 内容：`ListFilters` 新增 `skipTotal?: boolean`；`listRecords` 在 `skipTotal` 为真时跳过 `SELECT COUNT(*)`（`total` 置 0）。首页看板两处 `listRecords` 传入 `skipTotal: true`。`/api/records` 不传该值，搜索页 `total` 行为不变。首页 DB 往返从 4 次降到 2 次。

### 3. api-error 缩进修复（项 #6）
- 文件：`lib/api-error.ts`
- 内容：重排 `apiErrorFromUnknown` 与 `handleRouteError` 的异常缩进为顶层标准格式（纯格式修复，不改变运行时行为）。

### 4. ZodError 细节（项 #7）
- 文件：`lib/api-error.ts`
- 内容：`handleRouteError` 的 `ZodError` 分支将 `error.issues` 映射为 `{ path, message }[]`，经 `apiError` 的 `extra` 作为 `details` 返回。响应体变为 `{ error, details }`，向后兼容；`issues` 仅含字段路径与消息，不泄露 SQL / 堆栈。

### 5. 分隔符正则统一（项 #8）
- 新增 `lib/split.ts`，导出 `splitMultiValue(raw)`，规则 `/[\/\s、,，]+/`（兼容 `/`、空白、`、`、`,`、`，`），split 后 trim 并过滤空值。
- 替换 `app/detail/[id]/page.tsx` 4 处、`lib/queries.ts` 的 `listFacets` 2 处，并额外把客户端 `app/detail/[id]/DetailContent.tsx` 的 `splitMeta` 薄封装内联删除（直接调用 `splitMultiValue`），消除全站第 3 处重复正则及冗余封装。

### 6. i18n 冗余文案清理（追加）
- 文件：`lib/i18n/en.ts`、`lib/i18n/zh.ts`
- 内容：删除全站无引用的 4 个 key：`home.loading`、`detail.loading`、`detail.notFound`、`detail.notFoundGeneric`（en / zh 同步删除，键集仍一致）。
- 保留说明：`nav.home` / `nav.search` / `nav.report`、`footer.douban` / `footer.iblog` / `footer.github` 虽无字面量 `t("...")` 调用，但通过 `config.ts` 的 `NAV_LINKS` / `FOOTER_LINKS` 的 `key` 字段在 `Nav.tsx` / `Footer.tsx` 经 `{t(l.key)}` 动态引用；`site.title` / `site.description` 在 `app/layout.tsx` 与 `LanguageProvider.tsx` 直接引用——删除会破坏导航 / 页脚 / 页面标题，故保留。
